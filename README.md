# GradeHelper — 课程成绩助手

> **请接入 AI agent 前端使用！** 接入后可直接自然语言使用。

课程成绩助手是一个使用 AI 大模型辅助的课程成绩工具，可对课程报告、实验报告、试题、作业、试卷等材料自动评分，评分结果写入 Excel。

- 评分项、权重与评分标准完全由**评分模板**（xlsx 的 `rule` 表）决定：换课程、换报告类型只需换一个模板。
- 模型接口、路径与提示词均可在 `config.yaml` 中配置。
- ver 0.1.0，当前版本支持课程报告自动评分。

## 支持的文档类型

| 后缀 | 说明 |
| --- | --- |
| `.docx` | Word 文档（默认评分对象） |
| `.doc` | 旧版 Word 文档 |
| `.pdf` | PDF（含扫描版，支持 OCR） |

报告文件名必须符合 `课程名称-专业班级-学号-姓名-报告名`（或者在config.yaml中自定义模式，分隔符 `-`），不符合格式的文档会被忽略；程序只扫描报告目录**顶层**，不搜索子目录。

## 安装

需要 Python 3.11+：

```powershell
pip install -e .
```

## 快速上手

1. **放入报告**：把待评分文档放入同一目录，按上述规则命名。
2. **准备评分模板**（**至关重要！一定要测试调整模板**）：提供 xlsx 评分模板（`rule` 表定义评分项、权重、处理方法与评估标准），例如 `云安全-课程报告-评分模板.xlsx`。
3. **配置模型接口**：在 `config.yaml` 的 `endpoints.llm` 与 `endpoints.vllm` 中填入 `base_url`、`api_key`、`model`（本地无鉴权时 `api_key` 留空）。

一条命令跑完全部流程：

```powershell
python -m gradehelper --reports D:\AI\Reports --template 云安全-课程报告-评分模板.xlsx
```

按学号增量运行（只处理尚未评分的报告）：

```powershell
python -m gradehelper --reports D:\AI\Reports --template 云安全-课程报告-评分模板.xlsx --incremental true
```

## 评分模板要点

**评分模板至关重要！一定要测试调整模板！**
- Code 评分项：默认值可以改；但「评估方法」中的值如果改动，需要改程序代码（可以让前端AI agent改代码）。
- LLM 评分项：「评估方法」中的值可以改，大模型会自适应，无需改代码。
- 评分项修改：各评分项可让前端AI agent根据课程需要辅助修改。新增的code评分项，可以让前端AI agent添加；新增的LLM评分项，系统会自适应，无需改代码。

## 常用参数
因调试原因，默认值可能不准，请用参数指定。
| 参数 | 说明 |
| --- | --- |
| `--template XLSX` | 评分模板，**必填** |
| `--reports DIR` | 报告目录，默认当前工作目录 |
| `--output XLSX` | 结果文件路径；缺省时按规则生成在模板同目录 |
| `--tagDep NAME` | 系部专业标识，用于结果与日志文件名（默认 `系部专业`） |
| `--stage STAGE` | `doc` / `pic` / `pic-e` / `sen` / `full`（默认） / `full-e`；出错后可用 `--stage` 单独续跑某一步 |
| `--incremental true\|false` | 增量模式，只处理未完成部分；**必须显式给出值**，默认 `false` |
| `--files NAME...` | 只处理指定报告（文件主名或完整名，逗号/空格分隔） |
| `--skip-images N` | 跳过每份报告前 N 张图片（默认 2，如封面、评分表），各阶段需传相同值 |
| `-v, --verbose` | 控制台输出 DEBUG 级别日志 |
| `--config PATH` | 指定配置文件，默认项目根目录 `config.yaml` |
| `-h, --help` / `--version` | 查看参数帮助 / 版本号 |

完整参数参考与阶段机制见 [PROJECT.md](PROJECT.md)。

## 阶段与模式

程序可分为三个阶段，以及 `full` / `full-e`：

| 阶段 | 简单说明 |
| --- | --- |
| `doc` | 解析报告文档（docx/doc/pdf），Code 评分项程序化打分 |
| `pic` | 识别报告中的图片，把图片描述写回文档 |
| `pic-e` | 先查找图片对应的描述 txt：有就直接写回文档，没有才调用 vllm 识别 |
| `sen` | 用大模型对 LLM 评分项逐项评估，写入结果表 |
| `full` | 默认：依次执行 doc → pic → sen，一条命令跑完全部 |
| `full-e` | 依次执行 doc → pic-e → sen（图片阶段优先复用已有描述 txt） |

程序包含四种运行模式（由 `--files` 与 `--incremental` 组合决定）：

| 模式 | 含义 | 怎么指定 |
| --- | --- | --- |
| 全部全量 | 处理目录内全部文件，全部重新评分 | 默认（不加额外参数） |
| 全部增量 | 处理全部文件，跳过已完成的部分 | `--incremental true` |
| 指定全量 | 只处理 `--files` 指定的文件，且全部重新评分 | `--files 名单...` |
| 指定增量 | 只处理指定文件，并在其中跳过已完成部分 | `--files 名单... --incremental true` |

## 使用建议：

- **初次运行**：全部增量或全部全量，建议全部增量。
- **有学生补交作业**：全部增量、指定增量或指定全量，建议全部增量。
- **有学生修改作业**：指定全量。
- **改动code规则**：doc全量。
- **改动图片识别规则**：pic全量。
- **改动LLM规则**：sen全量。
- **stage-e**：谨慎使用，能节省图片二次识别时间，但误用会导致修改的作业不能正确更新图片描述。
- 建议多次运行sen阶段，取平均值，避免随机因素。多次评分，如果有异常值，建议增加运行次数，去掉异常值。

## 运行结果

- **评分结果**：与模板同目录的 `...评分结果.xlsx`（`result` 表），总分为 Excel 加权公式 `=分项1*权重1+分项2*权重2+...`。
- **运行日志**：与模板同目录的 `.log` 文件，记录运行配置、过程中的错误与阶段总结。
- 中断（Ctrl+C）时，已完成的评分/识别会保存；运行日志阶段总结按「全部 = 成功 + 失败 + 未处理」统计，并列出「失败文档」「未处理文档」的全名。

## 注意事项

- 多个阶段应使用**相同的** `--reports`、`--tagDep`、`--skip-images`，否则会读不到已有分数或图片与评分错位。
- 运行前请**关闭 Excel 中打开的结果文件**，否则程序会提示“结果文件无法写入”并以退出码 1 结束。
- 报告文件名不符合格式会被静默忽略——跑完发现没处理时先检查命名。
- 某一步失败后 `full` 会停止执行后续步骤；修复问题后可用 `--stage` 单独续跑。
- `pic-e` 与 `pic` 使用相同的产物：优先复用已有的 `...-Pn.txt` 描述（`paths.captions_dir` 为空时与 md 同目录），只把缺失描述的图片交给 vllm；适合已有识图结果、只想重新写入 md 或补齐少量图片的场景。
